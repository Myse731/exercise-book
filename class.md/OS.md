# 운영체제란?

## 1. 운영체제의 개요

- **정의**: 컴퓨터 하드웨어 바로 위에 설치되어 사용자 및 다른 모든 소프트웨어와 하드웨어를 연결하는 시스템 소프트웨어 계층입니다.
- **본질적 역할**: 응용 프로그램이나 사용자에게 모든 컴퓨터 자원을 숨기고, 정해진 인터페이스를 통해서만 제한적으로 자원을 사용할 수 있도록 안전한 환경과 결과를 제공합니다.

### 🎯 운영체제의 4대 목표

- **효율성**: 같은 자원으로 더 많은 작업을 처리하거나, 같은 작업량을 보다 적은 자원으로 처리하여 자원을 효율적으로 관리합니다.
- **안정성**: 사용자/응용 프로그램의 안전 및 하드웨어 보안을 처리하며, 시스템 오류 발생 시 이전으로 복구하는 **결함 포용(Fault Tolerance) 기능**을 수행합니다.
- **확장성**: 다양한 시스템 자원을 컴퓨터에 추가하거나 제거하기 편리하게 지원합니다.
- **편리성**: 사용자가 편리하게 작업할 수 있는 환경을 제공합니다.

## 2. 운영체제의 핵심 역할 및 인터페이스

### 🛡️ 운영체제의 주요 역할

- **자원 관리**: 응용 프로그램에 자원을 배분하고, 다수 요청 시 적절한 순서로 배분 및 회수하여 타 프로그램에 재할당합니다.
- **자원 보호**: 비정상적인 작업으로부터 컴퓨터 시스템 자원을 보호합니다.
- **하드웨어 인터페이스 제공**: CPU, 메모리, 키보드, 마우스 등 복잡한 장치들을 일관된 방식으로 사용하도록 지원합니다.
- **사용자 인터페이스 제공**: 사용자가 편리하게 제어할 수 있는 환경(예: GUI)을 제공합니다.

### 🔌 커널과 인터페이스 (협의 vs 광의)

- **커널 (협의의 OS)**: 프로세스, 메모리, 저장장치 관리 등 핵심 기능을 모아 놓은 OS의 핵심 부분으로, **메모리에 항시 상주**합니다.
- **인터페이스**: 커널에 사용자의 명령을 전달하고 실행 결과를 알려주는 역할을 담당합니다. (예: GUI)
- **광의의 운영체제**: 커널뿐만 아니라 각종 주변 시스템 유틸리티까지 포함한 넓은 개념입니다.
- **대표 예시**: Windows, macOS, Linux, iOS 등
- **임베디드 OS**: CPU 성능이 낮고 메모리가 작은 시스템에 내장되는 OS로, 해당 기기의 기능을 지속적으로 향상시킬 수 있게 해줍니다.

## 3. 시스템 호출과 디바이스 드라이버

### 🚪 시스템 호출 (System Call)

- **개념**: 커널이 자신과 자원을 보호하기 위해 만든 인터페이스입니다.
- **직접 접근의 문제**: 두 응용 프로그램이 임의의 위치에 데이터를 저장하려 하면 타인의 데이터가 훼손되거나 삭제될 수 있습니다.
- **시스템 호출의 해결 방식**: 응용 프로그램이 하드디스크에 직접 쓰지 않고 커널의 `write()` 함수를 통해 요청합니다. 커널이 데이터 입출력을 전적으로 책임지므로 자원 관리가 수월해집니다.

### 🔌 디바이스 드라이버 (Driver)

- **개념**: 커널과 하드웨어 간의 인터페이스를 담당합니다.
- **구분**: 마우스 같은 간단한 장치 드라이버는 커널이 자체 보유하지만, 그래픽 카드처럼 복잡한 HW는 제조사가 직접 드라이버를 제공합니다.

## 4. 커널의 구성 및 구조

### ⚙️ 커널의 5대 핵심 기능

| **핵심 기능** | **설명** |
| --- | --- |
| **프로세스 관리** | 프로세스에 CPU를 배분하고 작업에 필요한 제반 환경 제공 |
| **메모리 관리** | 프로세스에 작업 공간을 배치하며, 실제 메모리보다 큰 가상공간 제공 |
| **파일 시스템 관리** | 데이터를 저장하고 접근할 수 있는 인터페이스 제공 |
| **입출력 관리** | 필요한 입력과 출력 서비스 제공 |
| **프로세스 간 통신 관리** | 공동 작업을 위한 각 프로세스 간 통신(IPC) 환경 지원 |

### 🏗️ 커널의 구조 분류

- **단일형 구조 커널 (Monolithic Kernel)**
    - **특징**: 초창기 구조로, 커널의 핵심 기능 모듈들이 구분 없이 하나로 구성됨.
    - **장점**: 모듈 간 통신 비용이 적어 효율적인 운영 가능.
    - **단점**: 모듈이 묶여 있어 버그/오류 처리가 어렵고, 상호 의존성이 높아 작은 결함이 전체로 확산됨. 다양한 환경 적용이 어렵고 현대의 거대 OS에 적용하기 힘듦.
- **계층형 구조 커널 (Layered Kernel)**
    - 비슷한 기능을 가진 모듈을 묶어 하나의 계층을 만들고, 계층 간 통신으로 OS를 구현하는 방식.
- **마이크로 구조 커널 (Micro Kernel)**
    - 프로세스/메모리 관리, IPC 등 가장 기본적인 핵심 기능만 커널에 남겨 세분화함. 모듈 간 정보 교환은 프로세스 간 통신(IPC)을 통해 수행.

## 5. 가상 머신 (Virtual Machine)

- **개념**: 운영체제와 응용 프로그램 사이에서 작동하는 프로그램으로, 응용 프로그램이 모두 동일한 환경에서 작동하는 것처럼 만들어 줍니다.
- **대표 예시**: **JVM (Java Virtual Machine)** — Unix, Windows 등 다양한 OS 환경에서 작동하도록 배포되어 자바 프로그램의 플랫폼 독립성을 보장합니다.

## 6. 운영체제의 발전 역사

### 📅 시대별 발전 세대 요약

| **구분** | **시기** | **주요 기술** | **특징** |
| --- | --- | --- | --- |
| **0기** | 1940년대 | 없음 | 진공관(0과 1) 사용, OS 없음 |
| **1기** | 1950년대 | 카드 리더, 라인 프린터 | **일괄 작업 시스템**, OS의 등장 |
| **2기** | 1960년대 초 | 키보드, 모니터 | **대화형 시스템** |
| **3기** | 1960년대 후 | C언어 | 다중 프로그래밍, **시분할 시스템** |
| **4기** | 1970년대 | PC | 개인용 컴퓨터, **분산 시스템** |
| **5기** | 1990년대 | 웹 (Web) | **클라이언트/서버 시스템** |
| **6기** | 2000년대~ | 스마트폰 | **P2P, 그리드, 클라우드, 사물인터넷(IoT)** |

### 🔍 시대별 핵심 기술 상세 설명

- **애니악 (ENIAC)**
    - 백열전구 모양의 진공관 소자 사용 (On=1, Off=0).
    - 전선을 직접 연결하는 '하드 와이어링' 방식이며, **운영체제가 없었음**.
- **천공카드 & 일괄 작업 시스템 (Batch Processing)**
    - 천공카드 리더(입력)와 라인 프린터(출력)를 활용하여 모든 작업을 **한번에 일괄 처리**.
    - 실행 중간에 사용자 데이터 입력/수정이 불가능함.
    - **OS의 상주**: 메인 메모리가 OS 상주 영역과 사용자 영역으로 최초 분할됨.
- **대화형 시스템 (Interactive System)**
    - 모니터와 키보드의 등장으로 프로그램 진행 도중 사용자 입력을 받아 흐름을 변경 가능.
    - 문서 편집기, 게임 등 다양한 응용 프로그램 탄생의 계기가 됨.
- **다중 프로그래밍 & 시분할 시스템 (Time-Sharing System)**
    - **다중 프로그래밍**: 하나의 CPU로 여러 작업을 동시에 실행하는 기술.
    - **시분할 시스템**: CPU 사용 시간을 매우 잘게 쪼개어(**타임 슬라이스 / 타임 퀀텀**) 작업들에 배분함으로써 모든 작업이 동시에 처리되는 것처럼 보임 (현대 OS의 기초).
- **분산 시스템 (Distributed System)**
    - PC와 인터넷 보급으로 저가/소형 컴퓨터들을 네트워크로 묶어 대형 컴퓨터급 성능을 내도록 작업을 분산 처리 및 상호 교환.
- **클라이언트/서버 시스템 (Client/Server)**
    - 요청을 보내는 클라이언트와 요청을 처리하는 서버의 이중 구조 (웹 보급으로 대중화).
- **P2P 시스템 (Peer-to-Peer)**
    - 서버 과부하를 극복하기 위해 서버를 거치지 않고 **사용자와 사용자를 직접 연결**.
    - 냅스터(MP3 공유)에서 시작해 메신저, 토렌트 등에 활용.
    - *메신저*: 서버 부하 없이 수만 명이 채팅 및 파일 전송 가능.
    - *파일 공유*: N명에게 동시 수신 시 속도가 N배 빠르며, 일부 참여자가 이탈해도 지속 다운로드 가능.
- **그리드 컴퓨팅 (Grid Computing)**
    - 서로 다른 기종의 컴퓨터들을 묶어 대용량 컴퓨터 풀(Pool)을 구성하고 원격 연산을 수행 (종량제 컴퓨팅 환경).
    - **SaaS**가 소프트웨어의 필요 시 이용/정산 개념이라면, 그리드는 **하드웨어적 통합**에 초점. CPU, 저장소, 보안, 모니터링 등 표준 규약 생성에 기여.
- **클라우드 컴퓨팅 (Cloud Computing)**
    - **그리드 컴퓨팅 + SaaS**가 결합된 형태.
    - 인터넷을 통해 PC, 스마트폰 등 다양한 기기에서 데이터와 응용 프로그램을 언제 어디서나 자유롭게 이용하고 이동할 수 있는 환경.
- **사물 인터넷 (IoT, Internet of Things)**
    - 사물에 센서와 통신 기능을 내장해 인터넷에 연결하는 기술.
    - (예: 버스 도착 예정 시간, 가전 제어, 커넥티드 카, 스마트 그리드, 스마트 시티, 재난 방지 시스템 등)
    - 인터넷 연결 사물들이 데이터를 주고받아 **스스로 분석/학습한 정보를 제공**하거나 새로운 서비스를 창출함.

# 컴퓨터 구조와 성능향상

## 1. 하드웨어의 구성 및 구조

### 🛡️ 보호 장치 및 장치 제어기

- **Mode bit (모드 비트)**: 사용자 프로그램의 오작동으로 다른 프로그램 및 운영체제(OS)에 피해가 가지 않도록 보호하는 하드웨어 장치입니다.
    - **Mode bit 1 (사용자 모드)**: 사용자 프로그램을 수행하는 모드입니다.
    - **Mode bit 0 (커널 모드)**: 운영체제 코드를 수행하는 모드입니다.
    - Interrupt(인터럽트)나 Exception(예외) 발생 시 하드웨어가 mode bit를 0으로 자동 변경합니다.
    - 사용자 프로그램에 CPU 제어권을 넘기기 전 mode bit를 1로 세팅합니다.
- **Device Controller (장치 컨트롤러)**: 해당 I/O 장치 유형을 관리하는 일종의 작은 CPU입니다.
    - 제어 정보를 위해 **Control Register**, **Status Register**를 보유합니다.
    - 데이터 처리를 위한 일종의 Data Register인 **Local Buffer**를 보유합니다.
    - 실제 I/O 작업은 실제 Device와 Local Buffer 사이에서 발생합니다.
    - I/O 작업이 완료되면 Interrupt를 발생시켜 CPU에 작업 완료를 통보합니다.

### 🧩 컴퓨터의 핵심 구성 요소

| **구성 요소** | **핵심 역할** | **예시** |
| --- | --- | --- |
| **CPU** | 명령어를 해석하여 실행하는 장치 (인간의 두뇌에 해당) | Apple M 시리즈, Intel Core 등 |
| **메모리 (RAM)** | 작업에 필요한 프로그램과 데이터를 저장하는 장소

바이트 단위로 분할되며 공간마다 주소로 구분 | RAM |
| **입력장치** | 외부의 데이터를 컴퓨터에 입력하는 장치 | 키보드, 마우스 |
| **출력장치** | 컴퓨터에서 처리한 결과를 사용자가 원하는 형태로 출력하는 장치 | 모니터, 프린터 |
| **저장장치** | 메모리보다 느리지만 저렴하고 용량이 큼

전원 On/Off와 상관없이 데이터를 영구 저장 | SSD, HDD |
| **메인보드** | CPU, 메모리 등 여러 부품을 연결하는 판 (장치들은 버스를 통해 연결됨) | 메인보드 |
| **버스 (Bus)** | 컴퓨터 내부에서 데이터가 지나다니는 통로 | 데이터 버스, 제어 버스 등 |

### 🏛️ 폰 노이만 구조 (Von Neumann Architecture)

- CPU, 메모리, 입출력장치, 저장장치가 **버스**로 연결되어 있는 구조입니다.
- 프로그램은 저장장치에 담겨 있으나 직접 실행하지 못하며, **반드시 메인 메모리로 올라와야만 실행이 가능**합니다.
- 메인 메모리가 유일한 작업 공간이므로 메모리 관리가 매우 중요합니다.

> **Q. 저장장치에 프로그램 파일이 있는데도 메모리가 필요한 이유?**
> 
> 
> 저장장치는 느리고 메모리는 매우 빠르게 동작하며, 모든 프로그램은 CPU가 직접 접근할 수 있는 메모리에 올라와야 실행할 수 있기 때문입니다.
> 

## 2. CPU와 메모리

### ⚙️ CPU의 구성과 역할

- **산술논리연산장치 (ALU)**: 덧셈, 뺄셈 등의 산술 연산과 AND, OR 등의 논리 연산을 수행합니다.
- **제어장치 (Control Unit)**: CPU에서 작업을 지시하고 제어 신호를 생성합니다.
- **레지스터 (Register)**: CPU 내에서 데이터를 임시로 보관하는 가장 빠른 저장 장소입니다.

### 💾 메모리의 종류

- **RAM (휘발성)**: DRAM, SRAM, SDRAM
- **RAM (비휘발성)**: 플래시 메모리, FRAM, PRAM
- **ROM**: 마스크 롬(Mask ROM), PROM, EPROM

## 3. 버퍼와 캐시 (컴퓨터 성능 향상 기술)

### 🚀 속도 차이 완화 기술

- **버퍼 (Buffer)**: 속도 차이가 있는 두 장치 사이에서 일정량의 데이터를 모아 한 번에 옮김으로써 속도 차이를 완화하는 장치입니다.
- **캐시 (Cache)**: 메모리와 CPU 간의 속도 차이를 완화하기 위해 CPU가 앞으로 사용할 것으로 예상되는 데이터를 미리 가져와 저장해 두는 임시 장소입니다 (버퍼의 일종).

### 🎯 캐시의 동작 방식

- **캐시 히트 (Cache Hit)**: 캐시에서 원하는 데이터를 찾아 바로 사용하는 경우입니다.
- **캐시 미스 (Cache Miss)**: 원하는 데이터가 캐시에 없어 메인 메모리로 가서 데이터를 찾는 경우입니다.
- **캐시 적중률 (Hit Ratio)**: 캐시 히트가 발생하는 비율입니다. (일반적인 컴퓨터는 약 90% 이상)

### 📊 저장장치 계층 구조

용량이 커질수록 속도가 느려지고, 속도가 빠를수록 용량이 작고 비싸집니다.

$$\text{가장 빠른 순서} \longrightarrow \text{가장 느린 순서}$$

$$\text{레지스터} \longrightarrow \text{캐시} \longrightarrow \text{메모리} \longrightarrow \text{저장장치}$$

## 4. 인터럽트, 시스템 콜, DMA

### ⚡ 인터럽트 (Interrupt)

작업 중 인터럽트가 발생하면 현재 작업 시점의 PC (Program Counter)와 **레지스터** 값을 저장한 후 CPU의 제어권을 인터럽트 처리 루틴으로 넘깁니다.

- **하드웨어 인터럽트**: 하드웨어 장치가 발생시킨 인터럽트입니다.
- **소프트웨어 인터럽트**:
    - **Exception (예외)**: 프로그램이 오류를 범한 경우 발생합니다.
    - **System call (시스템 콜)**: 사용자 프로그램이 운영체제의 서비스를 받기 위해 커널 함수를 호출하는 경우입니다.

#### 🔄 인터럽트 방식의 입출력 동작 순서

CPU의 작업과 저장장치의 데이터 이동을 독립적으로 운영하여 시스템 효율을 높이는 방식입니다.

1. CPU가 입출력 관리자에게 입출력 명령을 보냅니다.
2. 입출력 관리자가 명령받은 데이터를 메모리로 가져오거나, 메모리의 데이터를 저장장치로 옮깁니다.
3. 데이터 전송이 끝나면 입출력 관리자가 CPU에 완료 신호(인터럽트)를 보냅니다.

### 🔑 시스템 콜과 DMA

- **System Call (시스템 콜)**: 사용자 프로그램이 OS의 서비스를 제공받기 위해 커널 함수를 호출하는 프로세스입니다.
- **Direct Memory Access (DMA, 직접 메모리 접근)**: 원래 메모리는 CPU의 전유 공간이지만, 입출력 관리자가 CPU의 개입(허락) 없이 직접 메모리에 접근하여 데이터를 읽거나 쓸 수 있도록 부여된 권한입니다.

# 프로세스와 스레드

## 5. 프로세스 (Process)

### 5-1. 정의 및 개념

- **프로그램**: 저장장치에 있는 정적인 상태입니다.
- **프로세스**: 실행을 위해 메모리에 올라온 동적인 상태입니다. (프로그램이 실행되어 메모리에 올라온 상태)

### 5-2. 프로세스의 메모리 구조

Plaintext

```
┌─────────────────────────────────────────┐
│ 1. 코드 영역 (Code Area)                 │  <- 읽기 전용 (Read-Only)
└────────────────────┬────────────────────┘
                     │
┌────────────────────▼────────────────────┐
│ 2. 데이터 영역 (Data Area)               │  <- 읽기 / 쓰기 가능 (Read/Write)
└────────────────────┬────────────────────┘
                     │
┌────────────────────▼────────────────────┐
│ 3. 스택 영역 (Stack Area)                │  <- 숨김 영역 (사용자에게 보이지 않음)
└─────────────────────────────────────────┘
```

- **코드 영역 (Code Area)**: 프로그램의 본문이 기술된 곳입니다. 프로그래머가 작성한 코드가 탑재되며 읽기 전용으로 처리됩니다.
- **데이터 영역 (Data Area)**: 코드가 실행되면서 사용하는 변수나 파일 등의 각종 데이터를 모아놓은 곳입니다. 데이터는 변하는 값이기 때문에 읽기와 쓰기가 모두 가능합니다.
- **스택 영역 (Stack Area)**: 운영체제가 프로세스를 실행하기 위해 부수적으로 필요한 데이터를 모아놓은 곳입니다. 프로세스 내에서 함수를 호출하면 수행 후 되돌아올 위치를 저장하며, 사용자에게는 보이지 않는 영역입니다.

### 5-3. 프로세스의 5가지 상태 및 보류 상태

| **상태** | **설명** |
| --- | --- |
| **생성 상태 (New)** | 프로그램이 메모리에 올라오고 OS로부터 프로세스 제어 블록(PCB)을 할당받은 상태입니다.

생성된 프로세스는 준비 상태로 이동하여 자기 순서를 기다립니다. |
| **준비 상태 (Ready)** | 실행 대기 중인 모든 프로세스가 자기 순서를 기다리는 상태입니다.

PCB는 준비 큐에서 기다리며 CPU 스케줄러에 의해 관리됩니다.

CPU 스케줄러가 `dispatch(PID)`를 실행하면 실행 상태로 전환됩니다. |
| **실행 상태 (Running)** | 프로세스가 CPU를 할당받아 실행되는 상태입니다.

타임 슬라이스를 다 사용하면 `timeout(PID)`가 실행되어 준비 상태로 이동합니다.

작업 완료 시 `exit(PID)`로 정상 종료되며, 입출력 요청 시 `block(PID)`가 실행되어 대기 상태로 이동합니다. |
| **대기 상태 (Waiting)** | 실행 상태의 프로세스가 입출력을 요청하고 완료될 때까지 기다리는 상태입니다.

입출력이 완료되어 인터럽트가 발생하면 `wakeup(PID)`에 의해 해당 프로세스의 PCB가 준비 상태로 이동합니다. |
| **완료 상태 (Terminated)** | 프로세스가 종료되는 상태입니다. 코드와 사용 데이터를 메모리에서 삭제하고 PCB를 폐기합니다.

비정상적인 강제 종료 시 디버깅을 위해 메모리 상태를 디스크로 옮기는데, 이를 **코어 덤프(Core Dump)**라 합니다. |
| **보류 상태 (Suspended)** | 프로세스가 메모리가 꽉 차거나, 프로그램 오류, 악의적 공격 판단, 긴 반복 주기, 입출력 지연 등으로 인해 **메모리 밖(디스크)으로 쫓겨난 상태**입니다. |

## 6. 프로세스 제어 블록과 스케줄러

### 📋 프로세스 제어 블록 (PCB)

프로세스를 실행하는 데 필요한 중요한 정보를 보관하는 자료구조로, 프로세스 생성 시 만들어지고 실행 완료 시 폐기됩니다.

- **PCB의 주요 구성 요소**:
    - **포인터**: 준비 상태나 대기 상태의 큐를 구현할 때 연결용으로 사용
    - **프로세스 상태**: 현재 프로세스의 상태 (New, Ready, Running, Waiting, Terminated)
    - **프로세스 구분자 (PID)**: 운영체제 내에서 프로세스를 식별하기 위한 고유 번호
    - **프로그램 카운터 (PC)**: 다음에 실행될 명령어의 메모리 주소 위치
    - **프로세스 우선순위**: 프로세스 실행 순서를 결정하는 우선순위 값
    - **각종 레지스터 정보**: 프로세스 실행 중 사용하던 레지스터 저장 값
    - **메모리 관리 정보**: 프로세스의 메모리 위치 정보, 경계 레지스터 및 한계 레지스터 값
    - **할당된 자원 정보**: 프로세스가 사용하는 입출력 자원이나 오픈된 파일 정보
    - **계정 정보**: 계정 번호, CPU 할당 시간, 사용 시간 등
    - **부모/자식 프로세스 구분자**: PPID(Parent PID) 및 CPID(Child PID)

### 🔄 문맥 교환 (Context Switch)

CPU를 차지하던 프로세스가 나가고 새로운 프로세스를 받아들이는 작업입니다. 실행 상태에서 나가는 PCB에는 지금까지의 작업 내용을 저장하고, 새로 들어오는 PCB의 내용으로 CPU 레지스터 환경을 다시 세팅합니다.

### ⏱️ 스케줄러의 종류

- **Long-term scheduler (장기 스케줄러 / Job Scheduler)**:
    - 시작 프로세스 중 어떤 것들을 ready queue로 보낼지 결정합니다.
    - 프로세스에 메모리 및 자원을 할당하는 문제입니다.
    - **Degree of Multiprogramming**(메모리에 올라간 프로세스 수)을 제어합니다.
    - 시분할 시스템(Time Sharing System)에는 보통 존재하지 않고 무조건 ready 상태로 만듭니다.
- **Short-term scheduler (단기 스케줄러 / CPU Scheduler)**:
    - 어떤 프로세스를 다음번에 실행시킬지 결정하고 CPU를 할당합니다.
    - millisecond 단위로 매우 빨라야 합니다.
- **Medium-term scheduler (중기 스케줄러)**:
    - 메모리 여유 공간 마련을 위해 프로세스를 통째로 디스크(Swap 영역)로 쫓아냅니다 (Swapping).
    - Degree of Multiprogramming을 제어합니다.

## 7. 프로세스의 생성, 복사, 전환

### 👯 `fork()` 시스템 호출 (프로세스 복사)

실행 중인 프로세스로부터 똑같은 새로운 프로세스를 복사하는 함수입니다. 원래 프로세스는 **부모 프로세스**, 새로 생긴 프로세스는 **자식 프로세스**가 됩니다.

- **동작 과정**: PCB를 포함한 부모 프로세스 영역의 대부분이 자식 프로세스에 복사됩니다. 단, **PID, 메모리 관련 정보, PPID/CPID**는 변경됩니다.
- **장점**:
    1. 프로세스의 생성 속도가 빠릅니다.
    2. 추가 작업 없이 자원을 상속받을 수 있습니다.
    3. 시스템 관리를 효율적으로 할 수 있습니다.

### 🔄 `exec()` 시스템 호출 (프로세스 전환)

기존의 프로세스를 삭제하지 않고 새로운 프로세스로 전환(재사용)하는 함수입니다.

- **동작 과정**: 코드 영역의 기존 내용을 지우고 새로운 코드로 바꿉니다. 데이터 영역은 새로운 변수로 채워지고 스택 영역은 리셋됩니다.
- **특징**: PID, PPID, CPID, 메모리 관련 정보 등 주요 식별자는 변하지 않으므로, 작업 종료 후 원래 부모 프로세스로 돌아갈 수 있습니다.

### 🌳 프로세스 계층 구조

유닉스(UNIX)의 모든 프로세스는 `init` 프로세스의 자식이 되어 트리 구조를 형성합니다.

Plaintext

```
         init (PID 1)
        /    \
     login    bash
     /          \
  user1        app
```

- **장점**:
    1. 여러 작업을 동시에 처리할 수 있습니다.
    2. 프로세스의 재사용이 용이합니다.
    3. 자원 회수가 쉽고 프로세스 간 책임 관계가 명확해집니다.

## 8. 스레드 (Thread)와 다중 처리

### 🧵 스레드의 정의 및 특징

- **CPU 입장에서의 작업 단위**: 운영체제 입장의 작업 단위는 프로세스이며, **CPU 입장의 작업 단위는 스레드**입니다.
- **개념**: 프로세스의 코드에 정의된 절차에 따라 CPU에 작업을 요청하는 실행 단위입니다.
- **자원 공유**: 같은 프로세스 내의 스레드들은 **Code, Data, OS resources를 서로 공유**합니다. (스택 영역은 독립적으로 보유)

### ⚔️ 프로세스 vs 스레드

- 프로세스끼리는 약하게 연결되어(독립된 메모리) 있는 반면, 스레드끼리는 강하게 연결되어(메모리 공유) 있습니다.
- 다중 스레드 구조에서는 하나의 서버 스레드가 대기 상태인 동안에도 동일한 태스크 내 다른 스레드가 실행되어 높은 처리율과 성능 향상을 얻을 수 있습니다.

### 🔄 멀티태스크, 멀티스레드, 멀티프로세싱 비교

| **구분** | **개념** | **특징 및 장단점** |
| --- | --- | --- |
| **멀티태스킹 (Multitasking)** | 여러 개의 프로세스를 실행하는 기법 | OS가 CPU 시간을 잘게 나누어 여러 프로세스에 배분합니다. |
| **멀티스레딩 (Multithreading)** | 하나의 프로세스 내를 여러 스레드로 구성하여 처리하는 기법 | **장점**: 응답성 향상, 자원 공유, 효율성 향상, 다중 CPU 지원

**단점**: 자원을 공유하므로 한 스레드의 문제가 전체 프로세스 중단으로 이어질 수 있음 (예: 브라우저 탭 하나 오류 시 전체 종료) |
| **멀티프로세싱 (Multiprocessing)** | 여러 개의 CPU(코어)를 사용하여 여러 스레드/프로세스를 동시 처리하는 기법 | 물리적인 하드웨어 성능을 극대화하는 환경입니다. |

# 스케줄링

## 1. 스케줄링의 개요 및 단계

### **1-1. 스케줄러의 3단계**

OS의 스케줄러는 식당 관리자처럼 여러 프로세스의 상황을 고려하여 CPU와 시스템 자원 배정을 결정합니다.

- **고수준 스케줄링 (High-level / Long-term / 작업 / 승인 스케줄링)**
    - 시스템 내의 **전체 작업 수를 조절**하며, 어떤 작업을 시스템이 받아들일지(승인) 거부할지 결정
    - 시스템 내에서 동시에 실행 가능한 프로세스의 총 개수를 정함
- **중간 수준 스케줄링 (Mid-level / Medium-term 스케줄링)**
    - 시스템 과부하 방지를 위해 **중지(Hold)와 활성화**로 활성 프로세스 수 조절
    - 일부 프로세스를 중지 상태로 보내어 나머지 프로세스가 원만하게 작동하도록 완충 역할 수행
- **저수준 스케줄링 (Low-level / Short-term / CPU 스케줄링)**
    - 어떤 프로세스에 **CPU를 할당할지, 대기 상태로 보낼지** 등을 아주 짧은 시간 단위로 결정
    - 실제로 **실제 작업을 수행**하도록 스케줄링함

```
[고수준] 작업 시작 여부 결정 (부하 조절)
    ↳ [중간 수준] 과부하 시 보류 상태로 이탈 (수 조절)
        ↳ [저수준] 실제 CPU 할당 및 작업 수행 (단기 실행)
```

### **1-2. CPU 스케줄링의 목적**

- **공평성:** 모든 프로세스가 공평하게 자원을 배정받아야 하며 특정 프로세스가 배제되어서는 안 됨
- **효율성:** 시스템 자원이 유휴 시간(Idle time) 없이 사용되어야 하며, 유휴 자원 요청 프로세스에 우선권 부여
- **안정성:** 우선순위를 이용해 중요 프로세스를 먼저 배정함으로써 자원 파괴/점유 시도로부터 시스템 보호
- **확장성:** 프로세스가 증가해도 안정적으로 작동해야 하며, 자원 추가 시 혜택이 시스템에 반영되어야 함
- **반응 시간 보장:** 응답이 없으면 멈춘 것으로 판단하므로 시스템은 적절한 시간 내에 요구에 반응해야 함
- **무한 연기 방지:** 특정 프로세스의 작업이 무한히 연기(Starvation)되어서는 안 됨

## 2. 선점/비선점, 우선순위 및 프로세스 분류

### **2-1. 선점형 vs 비선점형 스케줄링**

- **선점형 스케줄링 (Preemptive)**
    - OS가 필요 시 실행 중인 프로세스를 중단시키고 새로운 작업을 시작시키는 방식 (큐 느낌)
    - CPU 독점이 불가능하여 빠른 응답을 요구하는 **대화형 / 시분할 시스템**에 적합
    - 대부분의 저수준 스케줄러가 사용하는 방식
- **비선점형 스케줄링 (Non-preemptive)**
    - 프로세스가 CPU를 점유하면 종료되거나 자발적으로 대기할 때까지 빼앗기지 않는 방식 (스택 느낌)
    - 문맥 교환(Context Switch) 오버헤드가 적으나, 긴 프로세스로 인해 짧은 프로세스가 오랫동안 기다려 **전체 처리율이 떨어질 수 있음**
    - 과거 일괄 작업 시스템(Batch System)에서 주로 사용

| **구분** | **선점형 (Preemptive)** | **비선점형 (Non-preemptive)** |
| --- | --- | --- |
| **작업 방식** | 실행 중인 작업을 중단시키고 다른 작업 실행 가능 | 작업 완료 또는 자발적 대기 전까지 다른 작업 불가능 |
| **장점** | CPU 독점 방지, 대화형/시분할 시스템에 적합 | 스케줄러 작업량이 적고 문맥 교환 오버헤드가 적음 |
| **단점** | 문맥 교환 오버헤드가 많음 | 대기 프로세스가 많아져 전체 처리율이 떨어질 수 있음 |
| **사용 환경** | 시분할 방식 스케줄러 | 일괄 작업 방식 스케줄러 |
| **중요도** | 높음 | 낮음 |

### **2-2. 프로세스 우선순위**

- **커널 프로세스의 우선순위가 일반 프로세스보다 높음**
- 우선순위가 높은 프로세스가 CPU를 먼저, 더 오래 차지함
- 시스템 구현 방식에 따라 숫자가 클수록 높은 우선순위일 수도, 작을수록 높은 우선순위일 수도 있음

### **2-3. CPU 집중 vs 입출력(I/O) 집중 프로세스**

- **CPU 집중 프로세스:** 수학 연산 등 CPU를 많이 사용하는 프로세스 (**CPU 버스트가 많음**)
- **입출력(I/O) 집중 프로세스:** 저장장치 데이터 복사 등 I/O를 많이 사용하는 프로세스 (**I/O 버스트가 많음**)
- **스케줄링 원칙:** 입출력 집중 프로세스의 우선순위를 높여 먼저 처리해주면, I/O 작업 동안 CPU가 다른 일을 할 수 있어 **시스템 전체 효율이 향상됨**

### **2-4. 전면 vs 후면 프로세스**

- **전면 프로세스 (Foreground):** GUI 환경에서 화면 맨 앞에 위치하며, 현재 입력/출력을 사용해 사용자와 상호작용하는 프로세스 (상호작용 프로세스)
- **후면 프로세스 (Background):** 사용자 입력 없이 작동하는 프로세스 (일괄 작업 프로세스)
- **우선순위:** **전면 프로세스 > 후면 프로세스**

## 3. 다중 큐 (Multi-Queue)

### **준비 상태 큐 vs 대기 상태 큐**

- **준비 상태의 다중 큐 (Ready Queue):**
    - 프로세스는 생성/복귀 시 자신의 **우선순위에 해당하는 큐의 맨 뒤에 삽입**됨
    - CPU 스케줄러는 **우선순위가 가장 높은 큐의 맨 앞 프로세스**에 CPU를 할당
    - **한 번에 하나의 프로세스**를 꺼내어 CPU 할당
- **대기 상태의 다중 큐 (Waiting Queue):**
    - 시스템 효율을 위해 **같은 입출력(I/O)을 요구한 프로세스끼리 모아 놓음**
    - 여러 개의 프로세스 제어 블록(PCB)을 **동시에 꺼내어 준비 상태로 이동**
    - 동시에 끝나는 인터럽트 처리를 위해 **인터럽트 벡터(Interrupt Vector)** 자료구조 사용

## 4. 스케줄링 알고리즘 및 선택 기준

### **4-1. 알고리즘 분류 및 평가 기준**

- **알고리즘 분류**
    - **비선점형:** FCFS, SJF, HRN
    - **선점형:** 라운드 로빈(RR), SRT, 다단계 큐, 다단계 피드백 큐
    - **둘 다 가능:** 우선순위 스케줄링
- **평가 기준**
    - **CPU 사용률 (Utilization):** 전체 동작 시간 중 CPU가 일한 시간의 비율 (이상적 수치 100%, 실제는 90% 미만)
    - **처리량 (Throughput):** 단위 시간당 작업을 완료한 프로세스의 수 (수치가 클수록 우수)

### **4-2. FCFS (First-Come, First-Served)**

- **방식:** 준비 큐에 도착한 순서대로 CPU를 할당하는 **비선점형** 방식 (우선순위 동일)
- **평가:** 긴 프로세스가 CPU를 점유하면 뒤쪽 프로세스가 하염없이 기다려 시스템 효율 저하. 특히 작업 중 I/O 요청 시 CPU 유휴 시간이 늘어남

### **4-3. SJF (Shortest Job First)**

- **방식:** 준비 큐에서 **실행 시간이 가장 짧은 작업부터** CPU를 할당하는 **비선점형** 방식 (최단 작업 우선)
- **평가:** 콘보이 효과(Convoy Effect)를 완화하나, OS가 프로세스의 종료 시간을 정확히 예측하기 힘듦. 긴 작업은 계속 뒤로 밀려 **기아 현상(Starvation)** 발생
- **에이징 (Aging):** 기아 현상 완화책. 양보할 때마다 나이(Age)를 먹게 하여 상한선에 도달하면 무조건 실행되도록 규정

### **4-4. HRN (Highest Response Ratio Next)**

- **방식:** SJF의 기아 현상을 해결하기 위해 대기 시간과 CPU 사용 시간을 모두 고려하는 **비선점형** 방식 (최고 응답률 우선)
- **우선순위 계산식:**
    
    $$\text{우선순위} = \frac{\text{대기 시간} + \text{CPU 사용 시간}}{\text{CPU 사용 시간}}$$
    
- **평가:** 대기 시간이 길수록 분자가 커져 우선순위가 올라감. 기아 현상을 완화하지만 여전히 공평성에 위배되어 자주 쓰이지는 않음

### **4-5. 라운드 로빈 (Round Robin, RR)**

- **방식:** 할당된 시간(**타임 슬라이스**) 동안 작업 후 완료하지 못하면 준비 큐의 맨 뒤로 이동하는 대표적인 **선점형** 방식
- **타임 슬라이스 크기 조절:**
    - **너무 큰 경우:** FCFS와 다름없어짐
    - **너무 작은 경우:** 문맥 교환(Context Switch)이 빈번하게 발생하여 오버헤드로 인해 성능 저하
    - **결론:** 되도록 작게 설정하되 문맥 교환 오버헤드를 고려하여 적절히 설정 (UNIX 기준 약 100ms)

### **4-6. SRT (Shortest Remaining Time)**

- **방식:** 라운드 로빈 기본에, 남은 작업 시간이 가장 적은 프로세스를 선택하는 **선점형** 방식 (SJF의 선점형 버전)
- **평가:** 주기적으로 남은 시간을 계산해야 하고 문맥 교환이 추가됨. 종료 시간 예측 불가능 및 기아 현상으로 잘 사용되지 않음

### **4-7. 우선순위 (Priority) 스케줄링**

- **방식:** 프로세스의 중요도에 따른 우선순위를 반영 (선점/비선점 모두 적용 가능)
    - *비선점형 예:* SJF(작업시간 짧은 순), HRN(작업시간 짧거나 대기시간 긴 순)
    - *선점형 예:* SRT(남은시간 짧은 순)
- **우선순위 유형:**
    - **고정 우선순위:** 단순하지만 시시각각 변하는 시스템 상황을 반영하지 못함
    - **변동 우선순위:** 복잡하지만 상황을 반영하여 효율적 운용 가능
- **평가:** 순서를 무시하고 높은 우선순위를 먼저 처리하여 공평성 위배 및 기아 현상 유발. 매번 우선순위를 재계산할 경우 오버헤드 발생

### **4-8. 다단계 큐 (Multi-Level Queue)**

- **방식:** 우선순위에 따라 여러 개의 준비 큐를 사용하는 **고정 우선순위 선점형** 방식
- **특징:** 상단 큐의 모든 프로세스 작업이 끝나야만 하위 우선순위 큐의 작업이 시작됨 (하위 큐 기아 현상 가능성 존재)

### **4-9. 다단계 피드백 큐 (Multi-Level Feedback Queue)**

- **방식:** 다단계 큐의 기아 현상을 완화하기 위해 **CPU를 할당받을 때마다 프로세스의 우선순위를 한 단계씩 낮추는** 방식
- **특징:**
    - 우선순위가 낮아져도 커널 프로세스가 일반 프로세스 큐로 떨어지지는 않음
    - **낮은 우선순위 큐일수록 타임 슬라이스를 크게 설정**하여 CPU를 잡았을 때 많이 작업하도록 보장
    - **마지막 큐**는 무한대의 타임 슬라이스를 얻으며 **FCFS 방식으로 동작**
